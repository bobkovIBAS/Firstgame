# Roblox Standards

Версия 0.2.1. Общий Codex-плагин с документацией и шестью skills для разработки
Roblox-игр. Пакет находится в репозитории Firstgame, но применим к другим
играм: их палитра, объекты, механики и источник исходников определяются
профилем соответствующего проекта.

## Что входит

| Skill | Когда использовать |
| --- | --- |
| `roblox-init` | Проверить общие файлы и создать только недостающие |
| `roblox-setup` | Подключить общие стандарты к проекту, найти документацию и источник исходников |
| `roblox-ui` | Окна, кнопки, карточки, предпросмотр, состояния и адаптивность |
| `roblox-world` | Здания, окружение, модели и интерактивные точки |
| `roblox-vfx` | Следы, частицы, цвет, движение и читаемость эффектов |
| `roblox-testing` | План и выполнение проверки механики в Studio |

[Документация](docs/README.md) — общий справочник для людей и агентов.
[Шаблоны](templates/style-profile.md) — основа оформления конкретного проекта.

В пакете нет зависимости от платного API или собственного MCP-сервера.
Для работы с живой Studio потребуется отдельно подключённый Roblox Studio MCP
или другой согласованный способ редактирования. Без него можно работать
с файлами и планировать проверки, но нельзя заявлять об успешном живом тесте.

## Подключение каталога из локальной копии

Из корня клонированного репозитория:

```sh
codex plugin marketplace add .
codex plugin add roblox-standards@roblox-dev-kit
```

Каталог распространяет опубликованный плагин через источник `git-subdir`:
Codex получает `plugins/roblox-standards` из GitHub независимо от того,
какие папки присутствуют рядом с файлом marketplace. Даже при регистрации
каталога из локальной папки эта команда устанавливает опубликованную версию.
Непубликованные изменения проверяй скриптами ниже; для их установки сначала
опубликуй соответствующий Git ref или используй собственный локальный
каталог разработки с `source: local`.

Если клиент устанавливает плагины через интерфейс, после регистрации
marketplace открой каталог Plugins, выбери источник Roblox Development Kit
и установи Roblox Standards. Перезапусти клиент или начни новую сессию,
если skills ещё не появились. Добавление marketplace только регистрирует
каталог; установка плагина — отдельное действие.

## Подключение после публикации на GitHub

После push файлов пакета в `bobkovIBAS/Firstgame` на компьютере,
где этот marketplace ещё не зарегистрирован:

```sh
codex plugin marketplace add bobkovIBAS/Firstgame --ref main
codex plugin add roblox-standards@roblox-dev-kit
```

Для приватного репозитория понадобится Git-доступ участника. Чтобы работать
по опубликованному релизу, вместо `main` можно указать существующий Git-тег.
Тег `v0.1.0` станет доступен только после его создания и push.

Сам плагин копирует свои внутренние документы и шаблоны вместе со skills
и не зависит от соседнего файла игры. Источник `git-subdir` позволяет
загружать отдельно каталог marketplace и опубликованную папку плагина.

Если появляется `plugin source path is not a directory`, старый каталог
с `source: local` может ссылаться на папку, отсутствующую в скачанной копии.
После публикации исправленного каталога обнови его:

```sh
codex plugin marketplace upgrade roblox-dev-kit
codex plugin add roblox-standards@roblox-dev-kit
```

Для чистого повторного подключения можно удалить регистрацию старого
источника командой `codex plugin marketplace remove roblox-dev-kit`, затем
снова выполнить команды подключения из GitHub выше.

## Использование в любой игре

Открой папку нужной игры в Codex и запусти setup установленного плагина
либо выбери skill `roblox-init`. Команда проверит общие файлы и создаст
недостающее, сохраняя существующие документы. Для наполнения профиля
по текущей игре используй `roblox-setup`.

В пакет добавлен SessionStart hook для автоматической проверки при начале
Roblox-сессии. Его определение нужно один раз просмотреть и разрешить
в Codex через `/hooks`; установка плагина сама по себе не даёт hook доверие.
В Plan выполняется только проверка. Подробности и ручной запуск скрипта —
в [документации инициализации](docs/initialization.md).

Пример запроса: «Используй Roblox Standards, skill roblox-ui, чтобы добавить
окно коллекции в стиле текущего проекта». Для particles выбери `roblox-vfx`.
В CLI можно выбирать skill через `/skills` или упоминать его через `$`;
плагины могут показывать skill с префиксом пространства имён.

Список доступных skills зависит от установленного и включённого плагина.
Сам файл `AGENTS.md` внутри этого репозитория не применяется автоматически
к посторонним игровым репозиториям. Для них есть отдельный шаблон
[project-AGENTS.md](templates/project-AGENTS.md), который setup аккуратно
объединяет с существующими инструкциями.

## Проверка и публикация

Python 3.9+ без дополнительных зависимостей:

```sh
python3 plugins/roblox-standards/scripts/validate_plugin.py
python3 -B -m unittest discover -s plugins/roblox-standards/tests -v
git diff --check
```

Из корня Firstgame можно добавить только файлы, относящиеся к плагину:

```sh
git add .agents/plugins/marketplace.json plugins/roblox-standards .gitignore AGENTS.md README.md
git commit -m "Initialize reusable Roblox Standards plugin"
git push origin main
```

Эти команды — инструкция для публикации. Файлы пакета сами по себе
не означают commit, push или публикацию в публичном каталоге плагинов.
Локальная установка выполняется отдельно описанными выше командами.

При выпуске обновления меняй `version` в `plugin.json`, публикуй изменения
и согласовывай обновление версии с командой. Для зарегистрированного каталога:

```sh
codex plugin marketplace upgrade roblox-dev-kit
codex plugin add roblox-standards@roblox-dev-kit
```

Проверь новую сессию после обновления. Документация внутри установленного
пакета соответствует этой версии, а не автоматически последним изменениям
на GitHub. Доступность установки и обновления может различаться между
клиентами; в desktop можно переустановить пакет из обновлённого источника.

## Развитие стандартов

Общие договорённости меняй в `docs/`, процедуру применения — в `SKILL.md`,
а визуальные решения конкретной игры — в её проектной документации.
Новый skill нужен для отдельного рабочего процесса, а не для каждого
компонента или цвета. Изменения MCP и серверной инфраструктуры добавляются
отдельно, когда пакет должен работать с внешним сервисом.

Формат пакета: [OpenAI Plugins](https://developers.openai.com/plugins/build/plugins).
Обнаружение skills: [Build skills](https://learn.chatgpt.com/docs/build-skills).
