# Интерфейсы

## Сначала профиль проекта

Найди действующие палитру, типографику, размеры, способ построения UI и
образцы компонентов. Переиспользуй их роли: фон, поверхность, основной текст,
приглушённый текст, действие, выбранное и недоступное состояние.
Профиль игры определяет конкретные значения. Общий плагин не задаёт
всем играм один набор цветов или шрифтов.

Если профиля нет, опиши наблюдаемый стиль как текущий пример. Недостающие
решения выбирай в рамках задачи и явно обозначай новые предложения.
Не представляй случайные значения старого компонента как утверждённый стандарт.

## Состояния и действия

Разделяй выбранную для просмотра карточку, надетый предмет и подтверждённую
покупку. Нажатие кнопки не доказывает успешное серверное действие.
Показывай ожидание, результат или отказ, когда это важно для сценария.
Выделение цветом сопровождай понятной подписью или формой состояния.

Названия кнопок должны объяснять результат. Игроку нужны имя предмета,
условие получения, цена и состояние, если эти функции существуют.
Технические детали реализации оставляй в документации разработчиков.

Используй стабильные имена интерактивных объектов. Это помогает сопровождению
и автоматизации проверок. Предпросмотр должен очищаться при закрытии,
уходе из контекста и замене предмета. Если это локальный просмотр,
его объекты не должны менять общую игровую сцену для остальных игроков.

## Компоновка

Сохраняй иерархию: заголовок, основное содержимое, главное действие,
вспомогательные действия. Для коллекции выбирай сетку или список по контенту.
Не переноси абсолютную ширину настольного окна на узкий экран.
Смена расположения панелей, ограничение размеров и прокрутка должны
оставлять доступными действия и текст.

Поддерживай подходящий проекту ввод: мышь, сенсорный экран, клавиатура
или геймпад. Одного события наведения мыши недостаточно для важного действия
на устройстве без курсора. Конкретный перечень платформ берётся из профиля.

## Проверка

Проверь длинное название, выбранное состояние, отказ действия и закрытие.
На целевых размерах окна проверь обрезку текста, перекрытия и доступность
главной кнопки. Нажми реальные элементы интерфейса и сверь серверное состояние.
Скриншот и компиляция подтверждают разные свойства и не заменяют друг друга.

Ориентиры: [UI](https://create.roblox.com/docs/ui),
[тестирование устройств](https://create.roblox.com/docs/studio/testing-modes).
