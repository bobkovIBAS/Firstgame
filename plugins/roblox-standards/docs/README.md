# Общие стандарты Roblox

Этот справочник описывает паттерны, применимые к разным Roblox-играм.
При работе учитывай пользовательскую задачу, инструкции проекта и его
существующее оформление. Примеры не устанавливают единую тему для всех игр.

| Проверка результата | [Тестирование](testing.md) | `roblox-testing` |

## Где искать оформление игры

Сначала следуй существующим ссылкам из её `AGENTS.md` и README.
Если соглашения ещё нет, setup предлагает `docs/design/README.md` как точку
входа. В ней указываются тема, палитра, типографика, роли компонентов,
игровые примеры и ссылки на исходники. Для повторяемого сложного элемента
создаётся карточка в `docs/design/components/`.

Шаблоны: [профиль](../templates/style-profile.md),
[карточка элемента](../templates/component-pattern.md),
[правила для агента](../templates/project-AGENTS.md).
Существующие документы проекта можно использовать без переименования.

## Как поддерживать знания

Документируй решения, которые влияют на следующего разработчика: состояния
компонента, используемые токены, источник исходников, жизненный цикл и
наблюдаемые ограничения. Указывай статус — принятое правило, текущий пример,
прототип или предложение. План не подтверждает реализованную функцию.

Связывай описание с кодом или путём в Studio. При изменении принятого
паттерна обновляй описание вместе с реализацией. Новое правило должно иметь
понятную область применения; не превращай единичную особенность одной игры
в обязательное поведение всех проектов.

Skill описывает процедуру, справочник — само правило. Повторяющиеся значения
живут в runtime-конфигурации проекта, а документация объясняет их роли
и указывает, где их менять. Инструкции агента помогают применять правила,
но не заменяют проверку результата человеком и инструментами.
