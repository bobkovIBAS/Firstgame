# Команда roblox-init

`roblox-init` — отдельный skill и детерминированная команда инициализации.
Она проверяет общие файлы выбранной игры и создаёт недостающее. Повторный
запуск сохраняет существующее содержимое; палитра и настройки игры
автоматически не придумываются.

## Что проверяется

| Файл | Действие |
| --- | --- |
| `.roblox-standards.json` | Создать конфигурацию пути профиля, если её нет |
| `docs/design/README.md` | Создать начальный профиль, если собственного профиля нет |
| `docs/design/components/README.md` | Создать индекс карточек компонентов |
| `AGENTS.md` | Создать файл или дописать отсутствующий раздел Roblox Standards |
| `README.md` | Создать файл или дописать отсутствующую ссылку на профиль |

Путь профиля может отличаться. Без конфигурации команда переиспользует
первый существующий файл из `docs/design/README.md`, `docs/style/README.md`,
`docs/STYLE_GUIDE.md`, `STYLE_GUIDE.md`. Другой путь можно указать при первой
настройке через `--design-profile docs/visual/profile.md`; он сохраняется
в `.roblox-standards.json`. Существующую конфигурацию команда не переписывает.

Индекс компонентов создаётся рядом с выбранным профилем в `components/README.md`.
Если есть непустой `AGENTS.override.md`, маршрутизация дописывается в него,
поскольку Codex использует его вместо `AGENTS.md`. Существующие инструкции
и текст README сохраняются, одинаковые разделы повторно не добавляются.
Конфликт файла/каталога или некорректная конфигурация сообщаются как ошибка.

## Запуск в Codex

Выбери в плагине skill `roblox-init` или упомяни `$roblox-init`.
Он запускает скрипт установленного пакета для текущего целевого проекта.
Setup плагина также направлен на этот skill.

Для прямого запуска из клонированного репозитория:

```sh
python3 plugins/roblox-standards/scripts/init_project.py --project /путь/к/игре --json
```

Только проверить, без записи:

```sh
python3 plugins/roblox-standards/scripts/init_project.py --project /путь/к/игре --check --json
```

Коды завершения: 0 — выполнено или все файлы уже на месте; 1 — проверка
нашла недостающее; 2 — ошибка пути, конфигурации или доступа.
Создание документов не доказывает, что профиль уже заполнен и принят:
`roblox-setup` помогает дополнить его по текущей игре.

## Автоматически при начале сессии

В пакет включён `SessionStart` hook. После установки/включения плагина
Codex требует просмотр и доверие точному определению hook. В CLI это
делается через `/hooks`. Установка сама по себе не разрешает выполнение;
до доверия доступна ручная команда. Автоматический запуск происходит
при следующем старте, возобновлении или очистке сессии в поддерживаемом
локальном клиенте, а не как произвольный скрипт во время Git clone.

Hook распознаёт Roblox-проект по `.rbxl`, `.rbxlx`, `*.project.json` или
`.roblox-standards.json`. Он ищет ближайший такой каталог вверх от cwd
до границы Git-репозитория. В постороннем проекте или папке установленного
плагина он ничего не создаёт. В совершенно пустой папке сначала запусти
`roblox-init` вручную — это явно выбирает её как проект.

В режиме Plan hook выполняет только проверку. Для проектного отключения
автоматической инициализации установи `"auto_init": false` в
`.roblox-standards.json`; явный ручной запуск остаётся доступен.

Скрипту нужен Python 3.9+ и доступ к локальным файлам проекта. При ошибке
hook сообщает проблему в контекст и не блокирует сессию. Настройки доверия
плагин самостоятельно не изменяет. Пакет с lifecycle hooks предназначен
для локального/командного распространения; публичный каталог имеет отдельные
ограничения на такие hooks.

Источники: [Codex hooks](https://learn.chatgpt.com/docs/hooks),
[hooks и onboarding плагинов](https://developers.openai.com/plugins/build/plugins).
