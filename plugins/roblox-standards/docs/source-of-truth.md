# Источник исходников и совместная работа

Перед правкой установи, где находится актуальная версия затронутого объекта.
Это может быть файл, синхронизируемый Rojo/Script Sync, текущий Source в Studio
или согласованная версия бинарного place. Само наличие папки `src` ничего
не говорит о настроенной синхронизации.

Опиши выбранный процесс в документации конкретного проекта. Для разных
частей игры возможны разные источники: скрипты в файлах, геометрия в Studio.
Если связи между копиями нет, считай её ручной и сверяй содержимое.

При работе через MCP сначала определи нужный place и доступный DataModel.
Для существующего скрипта прочитай актуальный Source, для сцены — свойства
и окружение. Изменяй нужный участок и сохраняй соседние правки соавтора.
Снимок или локальная копия помогают восстановлению, но не являются поводом
переписать более новую общую версию.

Постоянные изменения применяй в Edit. Play подходит для наблюдения,
экспериментов и проверки; результат эксперимента переноси в постоянный
источник, если задача требует сохранения. После этого проверяй свежий запуск.
В Team Create учитывай используемый командой режим Live Scripting или Drafts;
локальный draft, общий Source и запущенная тестовая сессия могут различаться.

Не заявляй о синхронизации на чужой компьютер, публикации place или push
на GitHub по одному локальному сохранению. В отчёте указывай, куда внесено
изменение и какой запуск проверен. При недоступном Studio MCP продолжай
независимую работу с подтверждёнными файлами и обозначай границу проверки.

Первичные источники: [совместная работа](https://create.roblox.com/docs/projects/collaboration),
[Script Sync](https://create.roblox.com/docs/scripting/sync).
